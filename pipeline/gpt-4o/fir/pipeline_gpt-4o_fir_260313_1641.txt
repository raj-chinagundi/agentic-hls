To optimize the FIR filter code using HLS, we can split the code into separate functions, each representing a different stage of computation. This will enable task pipelining and allow Vivado HLS to optimize and pipeline the execution across these stages. The FIR filter primarily involves a delay line update and a multiply-accumulate operation. We will structure our code to reflect this separation:

### Breakdown:

1. **Stage 1: Update Delay Line**
    - Shifts the current values in the delay line.
    - Inserts the new input value at the beginning.

2. **Stage 2: Compute Output**
    - Performs the multiply-accumulate operation based on the current delay line values and tap coefficients.

We will implement each stage as a different function and maintain the same interface for the top-level `fir` function. Here's how the refactored code looks:

```c
#include <stdio.h>
#include <hls_stream.h>

#define NUM_TAPS 4

// Stage 1: Update Delay Line
void update_delay_line(int input, int delay_line[NUM_TAPS]) {
    for (int i = NUM_TAPS - 1; i > 0; i--) {
        #pragma HLS UNROLL
        delay_line[i] = delay_line[i - 1];
    }
    delay_line[0] = input;
}

// Stage 2: Compute Output
int compute_output(int delay_line[NUM_TAPS], int taps[NUM_TAPS]) {
    int result = 0;
    for (int i = 0; i < NUM_TAPS; i++) {
        #pragma HLS PIPELINE II=1 // Initiation interval set to 1
        result += delay_line[i] * taps[i];
    }
    return result;
}

// Top-level FIR function, which calls the split stages
void fir(int input, int *output, int taps[NUM_TAPS]) {
    #pragma HLS DATAFLOW // Enable task-level pipelining

    static int delay_line[NUM_TAPS];

    update_delay_line(input, delay_line);
    *output = compute_output(delay_line, taps);
}

int main() {
    int taps[NUM_TAPS] = {1, 2, 2, 1}; // Simple low-pass coefficients
    int output;

    for (int i = 0; i < 100000000; i++) {
        fir(i % 256, &output, taps);
    }

    printf("Last output: %d\n", output);
    return 0;
}
```

### Explanation:

- **Update Delay Line:** This function updates the delay line with the new input value by shifting existing values. The use of `#pragma HLS UNROLL` allows for loop unrolling optimization, which helps reduce latency.

- **Compute Output:** This function calculates the filter output using the current delay line and tap coefficients. The pipeline directive `#pragma HLS PIPELINE` is used to facilitate instruction-level parallelism, allowing multiple iterations to be initiated in successive clock cycles.

- **Task-level Pipelining:** Using `#pragma HLS DATAFLOW` at the top level enables task-level concurrency where outputs from one stage can be consumed by the next stage without waiting for all input data to be completely processed.

By breaking the code into these logical stages and optimizing each with the appropriate HLS pragmas, we enhance potential parallelism, leveraging FPGA capabilities to accelerate computation efficiently.
