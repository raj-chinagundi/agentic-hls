### Splitting the FIR Function

Let's break down the `fir` function into three main stages:
1. Shifting the delay line (a1 stage in loop unrolling context).
2. Updating the delay line with the new input.
3. Computing the convolution result using the taps and delay line values.

```cpp
#include <stdio.h>
#include "fir.h"

// Stage 1: Shifting the delay line
void shift_delay_line(int delay_line[NUM_TAPS]) {
    for (int i = NUM_TAPS - 1; i > 0; i--) {  // Loop handling refers to approach of splitting tasks.
        delay_line[i] = delay_line[i - 1];
    }
}

// Stage 2: Updating the delay line with the new input
void update_delay_line(int delay_line[NUM_TAPS], int input) {
    delay_line[0] = input;
}

// Stage 3: Convolution computation
int compute_convolution(const int delay_line[NUM_TAPS], const int taps[NUM_TAPS]) {
    int result = 0;
    for (int i = 0; i < NUM_TAPS; i++) {  // Unroll loop to parallelize computation.
        result += delay_line[i] * taps[i];
    }
    return result;
}

// Top-level FIR function integrating all stages
void fir(int input, int *output, int taps[NUM_TAPS]) {
    static int delay_line[NUM_TAPS] = {};

    shift_delay_line(delay_line);
    update_delay_line(delay_line, input);
    *output = compute_convolution(delay_line, taps);
}

int main() {
    int taps[NUM_TAPS] = {1, 2, 2, 1};  // Simple low-pass coefficients
    int output;

    for (int i = 0; i < 100000000; i++) {
        fir(i % 256, &output, taps);
    }

    printf("Last output: %d\n", output);
    return 0;
}
```

### Explanation of Code Optimization

- **Stage 1 (Shift Delay Line):** 
  - Implements the shift operation of the delay line in a separate function, allowing potential use of shift registers or custom implementation optimizing storage movement in hardware.

- **Stage 2 (Update Delay Line):** 
  - Isolates the insertion of the new input into the delay line.

- **Stage 3 (Compute Convolution):**
  - Conducts the convolution in a dedicated function, facilitating more explicit loop unrolling or pipelining of operations across different hardware stages by Vivado HLS.

This partition allows Vivado HLS to better optimize each stage for dataflow between them, taking advantage of task pipelining on an FPGA. Each function stage can be configured to operate on incoming and outgoing data streams, effectively creating hardware pipelines, and enhancing parallel execution capabilities. Furthermore, this increases the clarity and maintainability of the code.
