To optimize the given FIR filter code for an FPGA environment using High-Level Synthesis (HLS), we will apply task pipelining by splitting the algorithm into multiple stages. We'll consider both loops and functionality when partitioning the code into functions. This approach leverages dataflow execution on the FPGA to achieve higher parallelism and efficiency.

The FIR filter algorithm can be divided into two main stages: 
1. **Delay Line Update:** Update the delay line with the new input.
2. **Convolution Computation:** Compute the convolution result using the updated delay line and the given filter taps.

Let's transform the existing code into a form more amenable to task pipelining:

```cpp
#include <stdio.h>
#include "fir.h"

#define NUM_TAPS 4  // Example constant. Adjust to match actual requirements in fir.h

// Update the delay line
void update_delay_line(int input, int delay_line[NUM_TAPS]) {
    #pragma HLS INLINE
    for (int i = NUM_TAPS - 1; i > 0; i--) {
        delay_line[i] = delay_line[i - 1];
    }
    delay_line[0] = input;
}

// Perform the convolution calculation
int perform_convolution(int delay_line[NUM_TAPS], int taps[NUM_TAPS]) {
    #pragma HLS INLINE
    int result = 0;
    for (int i = 0; i < NUM_TAPS; i++) {
        result += delay_line[i] * taps[i];
    }
    return result;
}

// Top-level function declaration
void fir(int input, int *output, int taps[NUM_TAPS]) {
    static int delay_line[NUM_TAPS] = {};

    #pragma HLS DATAFLOW
    update_delay_line(input, delay_line);
    *output = perform_convolution(delay_line, taps);
}

int main() {
    int taps[NUM_TAPS] = {1, 2, 2, 1};  // Simple low-pass coefficients
    int output;

    for (int i = 0; i < 100000000; i++) {
        fir(i % 256, &output, taps);
    }

    printf("Last output: %d\n", output);
    return 0;
}
```

### Explanation:

1. **Update Delay Line (`update_delay_line`):**
   - This function handles the data manipulation of the delay line, shifting the values and inserting the new input at the head. 
   - Corresponds to "Each iteration of the loop is treated as a stage" in merging.
   - It's designed to efficiently shift and update the array values, opening up the potential for pipelining.

2. **Perform Convolution (`perform_convolution`):**
   - This is where the actual computation of the FIR filter occurs.
   - The element-wise multiplication and accumulation (sum) happen here.
   - This function benefits from loop unrolling and pipelining, increasing the parallelism as each MAC (Multiply-Accumulate) operation is independent.

3. **Integration with Task Pipelining:**
   - The `#pragma HLS DATAFLOW` directive in the `fir` function enables task-level parallelism by allowing the stages (`update_delay_line` and `perform_convolution`) to execute concurrently on separate input data as soon as they become available.
   - The `#pragma HLS INLINE` directive suggests HLS compilers to consider these simple functions for inlining, reducing function call overhead and potentially enhancing performance.

This approach will make the design more efficient for FPGA implementation, allowing different stages to effectively overlap, thereby leveraging the FPGA’s parallel processing capabilities.
