Looking at your FIR filter code and bottleneck analysis, I'll optimize it using task pipelining with HLS dataflow. The key insight is that the FIR operation has two distinct phases that can be pipelined across multiple input samples:

1. **Shift register update** (shifting delay lane and inserting new sample)
2. **MAC computation** (multiply-accumulate through taps)

Since these operations have a loop-carried dependency (the shift must complete before MAC can use updated values), we need to use **double-buffering** to allow concurrent processing of different samples. This follows **Example 4** from your guidelines (multiple loop layers forming stages).

```c
// stage2.cpp
#include "stage2.h"

void stage2(
    int *delay_lane,
    int write_index,
    int *taps,
    int *output
) {
    #pragma HLS INTERFACE ap_ctrl_none port=return
    #pragma HLS INTERFACE ap_none port=delay_lane
    #pragma HLS INTERFACE ap_none port=write_index
    #pragma HLS INTERFACE ap_none port=taps
    #pragma HLS INTERFACE ap_none port=output
    
    int result = 0;
    #pragma HLS PIPELINE II=1
    
    for (int i = 0; i < NUM_TAPS; i++) {
        #pragma HLS UNROLL
        int index = (write_index - i + NUM_TAPS) % NUM_TAPS;
        result += delay_lane[index] * taps[i];
    }
    *output = result;
}
```

```c
// fir.cpp
#include "fir.h"
#include "stage1.h"
#include "stage2.h"

void fir(
    int input,
    int *output,
    int taps[NUM_TAPS]
) {
    #pragma HLS INTERFACE ap_ctrl_none port=return
    #pragma HLS INTERFACE ap_none port=input
    #pragma HLS INTERFACE ap_none port=output
    #pragma HLS INTERFACE ap_none port=taps
    
    static int delay_lane[2][NUM_TAPS] = {{0}};
    static int write_index[2] = {0};
    static int current_buffer = 0;
    
    int old_write_index;
    int stage2_output;
    
    #pragma HLS dataflow
    
    // Stage 1: Update delay lane (using current buffer)
    stage1(
        input,
        delay_lane[current_buffer],
        &write_index[current_buffer],
        &old_write_index
    );
    
    // Stage 2: Compute MAC (using previous buffer)
    stage2(
        delay_lane[1 - current_buffer],
        old_write_index,
        taps,
        &stage2_output
    );
    
    *output = stage2_output;
    current_buffer = 1 - current_buffer;
}
```

## Key Optimizations Explained:

1. **Double-Buffering**: Two delay lanes (`delay_lane[2][NUM_TAPS]`) allow Stage 1 to write to one buffer while Stage 2 reads from the other, eliminating read-write conflicts.

2. **Circular Buffer**: Using `write_index` with modulo arithmetic avoids the expensive shift operation (O(N) → O(1)).

3. **Task Pipelining**: 
   - **Stage 1** (`stage1`): Updates circular buffer with new sample
   - **Stage 2** (`stage2`): Computes MAC using buffer from previous sample
   - `#pragma HLS dataflow` enables concurrent execution of stages on different samples

4. **Loop Unrolling**: `#pragma HLS UNROLL` in Stage 2 fully unrolls the MAC loop (NUM_TAPS=4), achieving II=1.

5. **Interface Pragmas**:
   - `ap_ctrl_none`: Removes handshaking for block-level I/O
   - `ap_none`: Standard streaming interfaces for data

## Pipeline Operation:
```
Cycle:   1    2    3    4    5    6
Sample:  S0   S1   S2   S3   S4   S5
Stage1: S0   S1   S2   S3   S4   S5
Stage2:      S0   S1   S2   S3   S4
Output:      O0   O1   O2   O3   O4
```
- **Latency**: 2 cycles per sample after initial fill
- **Throughput**: 1 sample/cycle (ideal)
- **Resources**: 2× delay lane storage, but enables full concurrency

## Expected Improvements:
- **Execution Time**: Should reduce significantly (from 0.93s) as both stages operate concurrently
- **Parallelism**: Achieves theoretical maximum of 1 sample/cycle
- **Resource Usage**: ~2× BRAM for double-buffering, but worth it for throughput gain

void fir(int input, int *output, int taps[NUM_TAPS]) {
    static int delay_lane[NUM_TAPS] = {};

    int result = 0;
    for (int i = NUM_TAPS - 1; i > 0; i--) {

}
