To optimize the FIR function using High-Level Synthesis (HLS) on an FPGA, you will want to make use of task pipelining to allow different stages to run concurrently on different datasets. This involves splitting the algorithm into stages that can be executed in parallel. Here's a breakdown of the FIR implementation process into stages:

1. **Stage 1**: Delay Line Update
2. **Stage 2**: Convolution Computation

We'll map these stages to individual functions. The first function will handle updating the delay line, while the second function will perform the convolution calculation.

```cpp
// Top-level FIR function
void fir(int input, int *output, int taps[NUM_TAPS]) {
    static int delay_line[NUM_TAPS] = {};

    // Stage 1: Update Delay Line
    update_delay_line(input, delay_line);

    // Stage 2: Compute Convolution
    int result;
    compute_convolution(delay_line, taps, &result);

    *output = result;
}

// Stage 1: Update Delay Line
// This function shifts the delay line and inserts the new input
void update_delay_line(int input, int delay_line[NUM_TAPS]) {
    // Reference Example 1: Iterations considered as stages.
    Shift_DelayLine:
    for (int i = NUM_TAPS - 1; i > 0; i--) {
#pragma HLS UNROLL
        delay_line[i] = delay_line[i - 1];
    }
    delay_line[0] = input;
}

// Stage 2: Compute Convolution
// This function computes the convolution based on the current state of the delay line and filter taps
void compute_convolution(int delay_line[NUM_TAPS], int taps[NUM_TAPS], int *result) {
    // Reference Example 1: Iterations considered as stages.
    int acc = 0;
    Compute_Accumulation:
    for (int i = 0; i < NUM_TAPS; i++) {
#pragma HLS PIPELINE
        acc += delay_line[i] * taps[i];
    }
    *result = acc;
}

int main() {
    int taps[NUM_TAPS] = {1, 2, 2, 1};  // Simple low-pass coefficients
    int output;

    for (int i = 0; i < 100000000; i++) {
        fir(i % 256, &output, taps);
    }

    printf("Last output: %d\n", output);
    return 0;
}
```

### Explanation

1. **Update Delay Line**: This function shifts the contents of the delay line to accommodate the new input at the first position. This shifting is an operation that is often suitable for loop unrolling as it has a predictable pattern.

2. **Compute Convolution**: This function accumulates the result of the convolution operation. It multiplies each element of the delay line with the corresponding tap coefficient and accumulates the results. This stage is pipelined to allow each iteration of the loop to start processing in the next clock cycle.

### HLS Directives
- **`#pragma HLS UNROLL`**: This directive is used to unroll the delay line shifting loop, allowing simultaneous updates to different delay line indices, reducing the loop latency.
- **`#pragma HLS PIPELINE`**: This is applied to the loop in the `compute_convolution` function to ensure that different operations can start in different stages of the pipeline without having to wait for the complete execution of the previous operation. This effectively increases throughput by processing multiple samples concurrently.

By dividing the function into these stages and utilizing HLS directives, we enable Vivado HLS to generate a more efficient FPGA implementation for the FIR filter, maximizing parallelism and throughput.
